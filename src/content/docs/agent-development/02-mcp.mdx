## The Integration Explosion

You have 5 AI applications — Claude, ChatGPT, Cursor, your custom app, a CI bot. They need to reach 8 tools — Jira, GitHub, Slack, PostgreSQL, Confluence, S3, email, a flight API.

Without a standard: **5 x 8 = 40 custom integrations.** Each with its own auth, data format, error handling, docs, and maintenance. Add one new tool? Five more integrations. Add one new AI client? Eight more.

Bu **N x M problemi**. Donanım sektörünün USB'den önce düştüğü tuzağın aynısı.

USB'den önceki dünyayı hatırlayın. Yazıcılar paralel port, fareler seri port, klavyeler PS/2, kameralar FireWire. Her cihazın kendi konektörü. Her bilgisayarda her port lazım.

USB bunu bitirdi. Tek standart. Her şey çalışır.

**MCP, AI dünyasının USB-C'si.** Tek protokol — herhangi bir AI client, herhangi bir tool server'la konuşabilir.

<KeyInsight>
MCP turns 40 custom integrations into 13. Build your tool once — it works with Claude, GPT, Cursor, and every future AI client that speaks the protocol. Build your client once — it works with every tool.
</KeyInsight>

<Aside type="tip">
MCP was created by Anthropic and open-sourced in late 2024. It's already adopted by Claude Desktop, Claude Code, Cursor, VS Code (GitHub Copilot), Zed, Windsurf, and many others. It's becoming the industry standard.
</Aside>

## Architecture: Three Layers

MCP tek bir bağlantı değil. Katmanlı bir sistem — separation of concerns prensibiyle. Bu ayrım güvenlik için kritik.

<FlowDiagram title="MCP Architecture">
  <div class="flow-row">
    <div class="flow-node secondary">
      <span class="node-icon">🏠</span>
      <span class="node-label">Host</span>
      <span class="node-desc">Claude Desktop, Cursor, your app</span>
    </div>
    <div class="flow-arrow animated">→</div>
    <div class="flow-node secondary">
      <span class="node-icon">📡</span>
      <span class="node-label">Client</span>
      <span class="node-desc">1:1 connection to a server</span>
    </div>
    <div class="flow-arrow animated">→</div>
    <div class="flow-node secondary">
      <span class="node-icon">⚡</span>
      <span class="node-label">Server</span>
      <span class="node-desc">Wraps an external tool</span>
    </div>
  </div>
</FlowDiagram>

<Steps>
1. **Host** — The application the user interacts with. It manages security, user consent, and spawns clients. Think Claude Desktop, Cursor, or your custom agent app.

2. **Client** — Lives inside the host. Each client maintains a 1:1 connection to a single MCP server. If one server crashes, the others keep running. Isolation by design.

3. **Server** — Exposes capabilities (tools, resources, prompts) over the protocol. It wraps an external system — a database, an API, a file system — and makes it accessible to AI in a standardized way.
</Steps>

Neden iki değil üç katman? **Güvenlik.** Host, AI'ın neye erişebileceğini kontrol eder. Client izolasyon sağlar — bozuk bir server diğerlerini zehirleyemez. Server sandbox'ta, sadece tasarlandığı şeyi açar.

## Transport: How Messages Move

MCP is transport-agnostic — it uses JSON-RPC 2.0 regardless of how messages are delivered. Two main options:

<Tabs>
  <TabItem label="stdio (Local)">
    The server runs as a **child process** of the host. Communication over stdin/stdout. The host spawns it, talks to it, kills it when done.

    ```json
    {
      "mcpServers": {
        "flight-data": {
          "command": "python",
          "args": ["flight_mcp_server.py"],
          "env": {
            "API_KEY": "your-key-here"
          }
        }
      }
    }
    ```

    **Best for**: Local development, CLI tools, personal automation. Zero network overhead.
  </TabItem>

  <TabItem label="Streamable HTTP (Remote)">
    The server runs as a **web service**. HTTP for requests, optional SSE for streaming. Works with load balancers, proxies, standard auth.

    ```json
    {
      "mcpServers": {
        "flight-data": {
          "url": "https://mcp.internal.example.com/flights",
          "headers": {
            "Authorization": "Bearer ${FLIGHT_API_TOKEN}"
          }
        }
      }
    }
    ```

    **Best for**: Production deployments, shared infrastructure, team-wide tools. This is the newer transport (2025) that supersedes the older HTTP+SSE approach.
  </TabItem>
</Tabs>

<Aside type="note">
Streamable HTTP is the recommended transport for production. It handles reconnection, supports both request-response and streaming, and integrates with existing HTTP infrastructure.
</Aside>

### Tools — Model-Controlled

Tool'lar AI'ın çağırmaya karar verdiği fonksiyonlar. En yaygın primitive — zamanınızın %90'ında bunu kullanacaksınız.

```python
from mcp.server import Server

server = Server("travel-flights")

@server.tool()
async def search_flights(
    origin: str,
    destination: str,
    date: str,
    passengers: int = 1
) -> str:
    """Search available flights between two airports on a given date.
    
    Args:
        origin: IATA airport code (e.g., 'CDG')
        destination: IATA airport code (e.g., 'NRT')
        date: Travel date in YYYY-MM-DD format
        passengers: Number of passengers (default: 1)
    
    Returns:
        Available flights with prices and schedules
    """
    results = await flight_api.search(origin, destination, date, passengers)
    return format_flight_results(results)
```

AI modeli tool adını, açıklamasını ve parametre şemasını görür — ne zaman ve nasıl çağıracağına kendisi karar verir. Docstring kritik: tool'unuzun AI için kullanma kılavuzu.

### Resources — Application-Controlled

Resource'lar AI'ın erişebildiği read-only veri. GET endpoint'leri gibi düşünün — host'un dahil etmeye karar verdiği bağlam.

```python
@server.resource("flights://status/{flight_number}")
async def get_flight_status(flight_number: str) -> str:
    """Get real-time status of a specific flight."""
    status = await flight_api.get_status(flight_number)
    return json.dumps(status, indent=2)
```

Resource'lar URI template'leri kullanır. AI mevcut olanları tarar, aksiyon almadan önce ihtiyacı olanı okur.

### Prompts — User-Controlled

Prompt'lar server'ın sunduğu yeniden kullanılabilir template'ler. Kullanıcı menüden seçer — AI'ın domain-specific görevlere nasıl yaklaşacağını standartlaştırır.

```python
@server.prompt()
async def disruption_analysis(flight_number: str) -> str:
    """Analyze a flight disruption and suggest rebooking options."""
    return f"""Analyze the disruption for flight {flight_number}.

Steps:
1. Check current flight status
2. Identify affected passengers
3. Search for alternative flights
4. Rank alternatives by: passenger tier, connection feasibility, cost
5. Generate a rebooking recommendation report"""
```

<KeyInsight>
**Tools** = model-controlled (AI decides to call them). **Resources** = application-controlled (host decides to include them). **Prompts** = user-controlled (user selects them). Three primitives, three control planes.
</KeyInsight>

## MCP in the Wild

Muhtemelen farkında olmadan MCP kullanıyorsunuzdur.

**Claude Code** has built-in MCP servers for file system operations, bash execution, and web fetching. Every time Claude Code reads a file or runs a command — that's MCP.

**Cursor and VS Code** support MCP servers. A common setup:

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": { "DATABASE_URL": "postgresql://localhost:5432/mydb" }
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" }
    }
  }
}
```

Artık editörünüzdeki AI asistanı veritabanınızı sorgulayabilir ve GitHub ile etkileşime geçebilir — standart bir protokol üzerinden. GitHub server'ını GitLab ile mi değiştirmek istiyorsunuz? Client kodu değişmez.

## Hands-On: Building an MCP Server

Sıfırdan bir flight information server yazacağız. Gerçek dünyada Flight API'lerini herhangi bir AI client'a açmak tam olarak böyle yapılır.

```python
# flight_mcp_server.py
import json
from mcp.server import Server
from mcp.server.stdio import stdio_server

server = Server("travel-flight-tools")

# Simulated flight data (in production, this calls a real API)
FLIGHTS_DB = {
    "AF1234": {
        "carrier": "Air France", "origin": "CDG", "destination": "NRT",
        "departure": "2025-03-15T10:30:00", "arrival": "2025-03-16T05:45:00",
        "status": "on_time", "aircraft": "A350-900", "passengers": 287
    },
    "AF5678": {
        "carrier": "Air France", "origin": "CDG", "destination": "JFK",
        "departure": "2025-03-15T14:00:00", "arrival": "2025-03-15T16:30:00",
        "status": "delayed", "delay_minutes": 45,
        "aircraft": "B777-300ER", "passengers": 342
    }
}

@server.tool()
async def get_flight_status(flight_number: str) -> str:
    """Get the current status of a flight by its flight number.

    Args:
        flight_number: The flight number (e.g., 'AF1234')

    Returns:
        Flight status including departure, arrival, and delay info
    """
    flight = FLIGHTS_DB.get(flight_number.upper())
    if not flight:
        return f"Flight {flight_number} not found."

    status_info = {
        "flight": flight_number.upper(),
        "carrier": flight["carrier"],
        "route": f"{flight['origin']} → {flight['destination']}",
        "status": flight["status"],
        "departure": flight["departure"],
        "arrival": flight["arrival"],
    }
    if flight.get("delay_minutes"):
        status_info["delay_minutes"] = flight["delay_minutes"]

    return json.dumps(status_info, indent=2)

@server.tool()
async def list_flights(origin: str = "", destination: str = "") -> str:
    """List available flights, optionally filtered by origin/destination.

    Args:
        origin: Filter by origin airport IATA code (optional)
        destination: Filter by destination airport IATA code (optional)
    """
    results = []
    for fn, data in FLIGHTS_DB.items():
        if origin and data["origin"] != origin.upper():
            continue
        if destination and data["destination"] != destination.upper():
            continue
        results.append({
            "flight_number": fn,
            "route": f"{data['origin']} → {data['destination']}",
            "departure": data["departure"],
            "status": data["status"]
        })

    if not results:
        return "No flights found matching the criteria."
    return json.dumps(results, indent=2)

async def main():
    async with stdio_server() as (read_stream, write_stream):
        await server.run(read_stream, write_stream)

if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
```

<DeepDive title="Advanced: Security and OAuth 2.1">

### Security Considerations

MCP introduces a new attack surface. Three defense layers:

**1. Tool Confirmation** — The host shows the user what tool is being called with what arguments before executing:

```
AI wants to call: delete_booking(booking_id="ABC123")
[Allow] [Deny] [Allow All for this session]
```

**2. Scoped Permissions** — Servers implement least-privilege access. A read-only server can never write:

```python
@server.tool()
async def search_flights(origin: str, destination: str) -> str:
    """Read-only search — no modifications allowed."""
    pass
```

**3. Input Validation** — Never trust tool inputs blindly. They come from the LLM, which can be manipulated via prompt injection:

```python
@server.tool()
async def query_database(sql_query: str) -> str:
    """Execute a read-only SQL query."""
    if not sql_query.strip().upper().startswith("SELECT"):
        return "Error: Only SELECT queries are allowed."
    
    async with read_only_pool.acquire() as conn:
        result = await conn.fetch(sql_query)
    return json.dumps(result)
```

### OAuth 2.1 for Remote Servers

Production Streamable HTTP servers integrate with existing identity providers (Active Directory, Okta) via OAuth 2.1. The client obtains an access token from the authorization server, then includes it as a Bearer token in MCP requests. This ensures corporate security policies are enforced at the protocol level.

</DeepDive>
