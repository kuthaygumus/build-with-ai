## Why Chains Aren't Enough

In Module 3, you built chains — linear sequences. Data flows in one direction. That works for "analyze this disruption." It fails completely for "handle this disruption."

Why? Because handling requires **decisions**.

After the decision point, the flow should split: minor disruptions auto-resolve, severe ones escalate to ops, critical ones trigger emergency protocol. A linear chain can't branch. It can't loop. It can't wait for human approval before proceeding. It can't retry a specific step while keeping the rest of the state intact.

**LangGraph** solves all of this by modeling your agent as a **graph** — nodes do work, edges control flow.

## Four Building Blocks

LangGraph has exactly four concepts. Everything else is built from these.

### 1. State — The Shared Memory

State is typed data that flows through your graph. Every node can read it and write to it.

```python
from typing import Annotated
from typing_extensions import TypedDict
from langgraph.graph.message import add_messages

class FlightDisruptionState(TypedDict):
    messages: Annotated[list, add_messages]  # Accumulates conversation history
    flight_number: str
    delay_minutes: int
    severity: str                # Set by the analysis node
    affected_passengers: list    # Set by the data retrieval node
    rebooking_plan: str          # Set by the planning node
    human_approved: bool         # Set by the human-in-the-loop step
```

<Aside type="note">
The `Annotated[list, add_messages]` pattern is key. `add_messages` is a **reducer** — instead of replacing the list each time, it appends new messages. This is how conversation history accumulates across nodes without overwriting.
</Aside>

### 2. Nodes — Functions That Do Work

Each node takes the current state, does something, and returns state updates.

```python
from langchain_anthropic import ChatAnthropic

model = ChatAnthropic(model="claude-sonnet-4-20250514")

async def analyze_disruption(state: FlightDisruptionState) -> dict:
    """Analyze the severity of a flight disruption."""
    prompt = f"""Analyze this flight disruption:
    Flight: {state['flight_number']}
    Delay: {state['delay_minutes']} minutes
    
    Classify severity as: minor (under 60 min), moderate (60-180 min), 
    severe (180-360 min), or critical (over 360 min).
    Respond with ONLY the severity word."""

    response = await model.ainvoke([{"role": "user", "content": prompt}])
    return {"severity": response.content.strip().lower()}


async def auto_resolve(state: FlightDisruptionState) -> dict:
    """Handle minor disruptions automatically."""
    return {
        "rebooking_plan": f"Auto-resolved: {state['flight_number']} - "
                          f"minor delay of {state['delay_minutes']}min. "
                          f"Passengers notified via SMS.",
        "messages": [{"role": "assistant",
                      "content": "Minor disruption auto-resolved."}]
    }


async def escalate_to_ops(state: FlightDisruptionState) -> dict:
    """Escalate severe disruptions to operations team."""
    prompt = f"""Create a rebooking plan for flight {state['flight_number']}.
    Severity: {state['severity']}, Delay: {state['delay_minutes']} minutes.
    Consider: alternative flights, hotels, meal vouchers, premium priority."""

    response = await model.ainvoke([{"role": "user", "content": prompt}])
    return {
        "rebooking_plan": response.content,
        "messages": [{"role": "assistant",
                      "content": "Escalated: Rebooking plan created for review."}]
    }
```

### 3. Edges — The Wiring

Two types. **Normal edges** always go from A to B. **Conditional edges** choose the next node based on state.

```python
# Normal edge — always goes this way
graph.add_edge("analyze", "fetch_passengers")

# Conditional edge — decides at runtime
def route_by_severity(state: FlightDisruptionState) -> str:
    if state["severity"] in ("minor",):
        return "auto_resolve"
    elif state["severity"] in ("moderate", "severe"):
        return "escalate_to_ops"
    else:
        return "emergency_protocol"

graph.add_conditional_edges(
    "analyze",
    route_by_severity,
    {
        "auto_resolve": "auto_resolve",
        "escalate_to_ops": "escalate_to_ops",
        "emergency_protocol": "emergency_protocol",
    }
)
```

### 4. The Lifecycle

<Steps>
1. **Define** — Create a `StateGraph` with your state schema
2. **Add nodes** — Register functions as named nodes
3. **Add edges** — Wire nodes with normal or conditional edges
4. **Set entry point** — Which node runs first
5. **Compile** — Convert to an executable `CompiledGraph`
6. **Invoke** — Run with initial state
</Steps>

## Building Your First Graph

All four concepts, wired together into a runnable graph:

```python
from langgraph.graph import StateGraph, START, END
from typing import Annotated
from typing_extensions import TypedDict
from langgraph.graph.message import add_messages
from langchain_anthropic import ChatAnthropic

class ResearchState(TypedDict):
    messages: Annotated[list, add_messages]
    topic: str
    research_notes: str
    summary: str

model = ChatAnthropic(model="claude-sonnet-4-20250514", temperature=0)

async def research(state: ResearchState) -> dict:
    response = await model.ainvoke([
        {"role": "system", "content": "You are a thorough researcher. "
         "Provide detailed, factual notes about the given topic."},
        {"role": "user", "content": f"Research this topic: {state['topic']}"}
    ])
    return {"research_notes": response.content}

async def summarize(state: ResearchState) -> dict:
    response = await model.ainvoke([
        {"role": "system", "content": "Condense research notes into "
         "a clear, 3-paragraph summary."},
        {"role": "user", "content": f"Summarize:\n\n{state['research_notes']}"}
    ])
    return {
        "summary": response.content,
        "messages": [{"role": "assistant", "content": response.content}]
    }

# Build
workflow = StateGraph(ResearchState)
workflow.add_node("research", research)
workflow.add_node("summarize", summarize)
workflow.add_edge(START, "research")
workflow.add_edge("research", "summarize")
workflow.add_edge("summarize", END)

graph = workflow.compile()

result = await graph.ainvoke({
    "topic": "Impact of AI agents on airline operations",
    "messages": []
})
```

## Conditional Routing: The Decision Graph

Now the real power. A customer request router that classifies incoming requests and routes them to specialized handlers:

```python
from langgraph.graph import StateGraph, START, END

class CustomerRequestState(TypedDict):
    messages: Annotated[list, add_messages]
    request_text: str
    category: str        # "rebooking", "complaint", "inquiry"
    response: str

async def classify_request(state: CustomerRequestState) -> dict:
    response = await model.ainvoke([
        {"role": "system",
         "content": "Classify the customer request into exactly one category: "
                    "rebooking, complaint, or inquiry. Respond with ONLY the category."},
        {"role": "user", "content": state["request_text"]}
    ])
    return {"category": response.content.strip().lower()}

async def handle_rebooking(state: CustomerRequestState) -> dict:
    response = await model.ainvoke([
        {"role": "system",
         "content": "You are a rebooking specialist. Find alternative flights. "
                    "Be efficient and solution-oriented."},
        {"role": "user", "content": state["request_text"]}
    ])
    return {"response": response.content}

async def handle_complaint(state: CustomerRequestState) -> dict:
    response = await model.ainvoke([
        {"role": "system",
         "content": "Handle complaints with empathy. Acknowledge, apologize, resolve."},
        {"role": "user", "content": state["request_text"]}
    ])
    return {"response": response.content}

async def handle_inquiry(state: CustomerRequestState) -> dict:
    response = await model.ainvoke([
        {"role": "system",
         "content": "Answer travel inquiries. Be helpful and informative."},
        {"role": "user", "content": state["request_text"]}
    ])
    return {"response": response.content}

def route_request(state: CustomerRequestState) -> str:
    category = state["category"]
    if category == "rebooking":
        return "handle_rebooking"
    elif category == "complaint":
        return "handle_complaint"
    return "handle_inquiry"

# Build the graph
workflow = StateGraph(CustomerRequestState)
workflow.add_node("classify", classify_request)
workflow.add_node("handle_rebooking", handle_rebooking)
workflow.add_node("handle_complaint", handle_complaint)
workflow.add_node("handle_inquiry", handle_inquiry)

workflow.add_edge(START, "classify")
workflow.add_conditional_edges(
    "classify", route_request,
    {
        "handle_rebooking": "handle_rebooking",
        "handle_complaint": "handle_complaint",
        "handle_inquiry": "handle_inquiry",
    }
)
workflow.add_edge("handle_rebooking", END)
workflow.add_edge("handle_complaint", END)
workflow.add_edge("handle_inquiry", END)

graph = workflow.compile()
```

## Human-in-the-Loop

For production agents, you need a human to approve before the agent executes irreversible actions. LangGraph has first-class support via `interrupt_before` and `interrupt_after`.

```python
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()

graph = workflow.compile(
    checkpointer=checkpointer,
    interrupt_before=["execute_rebooking"]  # Pause BEFORE this node
)

# Run until the interrupt
config = {"configurable": {"thread_id": "request_001"}}
result = await graph.ainvoke(initial_state, config)

# Graph is paused. Show the plan to a human:
print("Proposed rebooking plan:")
print(result["rebooking_plan"])

# Human approves... resume execution:
result = await graph.ainvoke(None, config)
```

<Aside type="caution">
`interrupt_before` and `interrupt_after` require a **checkpointer**. The checkpointer persists graph state so it can be resumed later — even in a different process. `MemorySaver` is fine for development. Production needs PostgreSQL or Redis.
</Aside>

<KeyInsight>
Human-in-the-loop isn't a hack bolted on after the fact. It's a first-class feature of LangGraph. The graph pauses, persists its state, waits for human input, and resumes exactly where it left off. This is how you build agents people actually trust.
</KeyInsight>

## Multi-Agent Collaboration

The most powerful LangGraph pattern: multiple specialized agents that iterate until quality is met.

```python
class MultiAgentState(TypedDict):
    messages: Annotated[list, add_messages]
    task: str
    research_output: str
    review_feedback: str
    final_report: str
    iteration: int

async def researcher(state: MultiAgentState) -> dict:
    """Agent 1: Researches and produces a draft report."""
    context = ""
    if state.get("review_feedback"):
        context = f"\n\nPrevious feedback to address:\n{state['review_feedback']}"

    response = await model.ainvoke([
        {"role": "system",
         "content": "You are a thorough researcher. Produce a detailed report."},
        {"role": "user",
         "content": f"Task: {state['task']}{context}"}
    ])
    return {
        "research_output": response.content,
        "iteration": state.get("iteration", 0) + 1
    }

async def reviewer(state: MultiAgentState) -> dict:
    """Agent 2: Reviews and provides feedback or approves."""
    response = await model.ainvoke([
        {"role": "system",
         "content": "You are a critical reviewer. Evaluate for accuracy, "
                    "completeness, clarity. If good enough, say APPROVED. "
                    "Otherwise, provide specific feedback."},
        {"role": "user",
         "content": f"Review this report:\n\n{state['research_output']}"}
    ])
    return {"review_feedback": response.content}

def should_continue(state: MultiAgentState) -> str:
    if "APPROVED" in state["review_feedback"].upper():
        return "finalize"
    if state["iteration"] >= 3:
        return "finalize"
    return "revise"

async def finalize(state: MultiAgentState) -> dict:
    return {"final_report": state["research_output"]}

# Build the multi-agent graph
workflow = StateGraph(MultiAgentState)
workflow.add_node("researcher", researcher)
workflow.add_node("reviewer", reviewer)
workflow.add_node("finalize", finalize)

workflow.add_edge(START, "researcher")
workflow.add_edge("researcher", "reviewer")
workflow.add_conditional_edges(
    "reviewer", should_continue,
    {"revise": "researcher", "finalize": "finalize"}
)
workflow.add_edge("finalize", END)

graph = workflow.compile()
```

### Subgraphs — Modular Agent Design

Complex agents compose from smaller graphs. A subgraph is a compiled graph used as a node in a parent graph:

```python
# Subgraph for passenger handling
passenger_workflow = StateGraph(PassengerState)
passenger_workflow.add_node("check_tier", check_passenger_tier)
passenger_workflow.add_node("find_alternatives", find_alternative_flights)
passenger_workflow.add_node("rebook", execute_rebooking)
passenger_subgraph = passenger_workflow.compile()

# Use as a node in the parent graph
main_workflow = StateGraph(DisruptionState)
main_workflow.add_node("analyze", analyze_disruption)
main_workflow.add_node("handle_passengers", passenger_subgraph)
main_workflow.add_node("report", generate_report)
```

Each subgraph is independently testable. Compose complexity from simple, validated pieces.

### Persistent Checkpointing

For production, state survives process restarts:

```python
from langgraph.checkpoint.postgres.aio import AsyncPostgresSaver

async with AsyncPostgresSaver.from_conn_string(
    "postgresql://user:pass@localhost:5432/agents"
) as checkpointer:
    graph = workflow.compile(checkpointer=checkpointer)
    config = {"configurable": {"thread_id": "disruption_AF1234"}}
    result = await graph.ainvoke(initial_state, config)
```

### LangSmith — See Inside Your Graph

Every node execution, every LLM call, every state update — traced automatically:

```python
import os
os.environ["LANGSMITH_TRACING"] = "true"
os.environ["LANGSMITH_API_KEY"] = "your-key"
os.environ["LANGSMITH_PROJECT"] = "agent-training"

# Every invocation is now traced at smith.langchain.com
```

LangSmith shows: node execution order, input/output per LLM call, token usage and latency per step, where errors occurred, full state at every checkpoint. Invaluable for debugging and cost management.
