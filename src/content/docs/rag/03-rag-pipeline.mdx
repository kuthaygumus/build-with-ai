## Stage 2: Chunking — The Make-or-Break Decision

This is the single most impactful decision in your RAG pipeline. **Bad chunking ruins everything downstream.** Great retrieval can't fix chunks that split sentences mid-thought. Great prompts can't fix chunks that mix three unrelated topics.

<KeyInsight>
Chunking determines retrieval quality. Retrieval quality determines answer quality. Get this wrong, and nothing downstream can save you.
</KeyInsight>

Why chunk at all? Three reasons:
1. LLMs have context limits — you can't stuff the entire knowledge base into a prompt
2. Embedding models work best on focused passages, not 50-page documents
3. Retrieval is more precise with smaller, topically coherent chunks

Tüm dokümanı embed etme vs paragraf paragraf embed etme farkını gösterin. Full-document embedding her şeyle zayıf eşleşir, paragraf embedding doğru paragrafla güçlü eşleşir. Sorun: "chunk_size=2000 ile chunk_size=500 arasındaki fark ne olur?" Notebook'ta deneyin.

### Strategy 1: Recursive Character Splitting — The Default

Tries natural boundaries first (paragraphs, then sentences, then words), falls back to smaller separators as needed:

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
    separators=[
        "\n\n",    # First: paragraph breaks
        "\n",      # Then: line breaks
        ". ",      # Then: sentence endings
        ", ",      # Then: clause breaks
        " ",       # Then: word boundaries
        ""         # Last resort: character by character
    ]
)

chunks = splitter.split_documents(documents)
print(f"Created {len(chunks)} chunks from {len(documents)} documents")
```

**This is your starting point.** Use this until you have a specific reason not to.

### Strategy 2: Semantic Chunking

Uses embeddings to detect topic boundaries. Splits when semantic similarity between consecutive sentences drops below a threshold:

```python
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings

splitter = SemanticChunker(
    embeddings=OpenAIEmbeddings(model="text-embedding-3-small"),
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=75
)

chunks = splitter.split_documents(documents)
# Chunks follow natural topic boundaries
```

**Pros**: Topically coherent chunks. **Cons**: Variable sizes, slower (requires embedding during indexing).

### Strategy 3: Document-Structure-Aware

Uses the document's own structure — headings, sections — to define chunks:

```python
from langchain.text_splitter import MarkdownHeaderTextSplitter

headers_to_split_on = [
    ("#", "h1"),
    ("##", "h2"),
    ("###", "h3"),
]

splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=headers_to_split_on
)

# Each chunk inherits its header hierarchy as metadata
chunks = splitter.split_text(markdown_text)
# Headers: {'h1': 'Flight Offers API', 'h2': 'Search Endpoint'}
# Content: The search endpoint accepts origin, destination, and date...
```

**Ideal for**: Markdown docs, API references, structured manuals.

<Aside type="caution">
**Rule of thumb**: Start with `chunk_size=500-1000` and `chunk_overlap=100-200`. Then experiment. The right size depends on your content and queries — there is no universal answer. Benchmark, don't guess.
</Aside>

## Stage 3: Retrieval

User asks a question. You need to find the most relevant chunks. Three approaches:

### Dense Retrieval (Semantic Search)

Embed the query, find the nearest vectors. This is what you built in Module 2:

```python
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector_store = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embeddings
)

retriever = vector_store.as_retriever(search_kwargs={"k": 5})
results = retriever.invoke("How do I authenticate with the Flight API?")
```

**Strength**: Understands meaning. "How do I log in?" matches docs about "authentication."
**Weakness**: Misses exact terms, codes, acronyms.

### Sparse Retrieval (BM25 / Keyword)

Traditional keyword search. No embeddings. No meaning. Just term matching:

```python
from langchain_community.retrievers import BM25Retriever

bm25_retriever = BM25Retriever.from_documents(chunks, k=5)
results = bm25_retriever.invoke("PNR AMAXTK error code 4812")
```

**Strength**: Exact term matching. Error codes, PNR locators, acronyms.
**Weakness**: "delayed flight" won't match "late arrival."

### Hybrid Retrieval — Best of Both

This is the production default. Combine dense and sparse, merge results:

```python
from langchain.retrievers import EnsembleRetriever

hybrid_retriever = EnsembleRetriever(
    retrievers=[
        vector_store.as_retriever(search_kwargs={"k": 5}),
        BM25Retriever.from_documents(chunks, k=5)
    ],
    weights=[0.5, 0.5]
)

results = hybrid_retriever.invoke("OAuth2 credentials for flight-offers v2")
# Finds results matching semantically AND by keyword
```

## Stage 4: Generation

You have relevant chunks. Now generate a grounded answer.

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

llm = ChatOpenAI(model="gpt-4o", temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", """You are a travel technology support assistant.
Answer based ONLY on the provided context.
If the context doesn't contain the answer, say "I don't have enough information."

Rules:
- Be precise and technical
- Cite sources using [Source: filename, page X] format
- If sources conflict, mention the discrepancy

Context:
{context}"""),
    ("human", "{question}")
])

def format_context(docs):
    return "\n\n---\n\n".join([
        f"[Source: {doc.metadata.get('source', 'unknown')}, "
        f"Page: {doc.metadata.get('page', 'N/A')}]\n"
        f"{doc.page_content}"
        for doc in docs
    ])
```

### The Full Pipeline — 25 Lines

Everything together:

```python
from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_chroma import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

# OFFLINE: Load, Chunk, Embed, Store
docs = PyPDFLoader("flight-api-guide.pdf").load()
chunks = RecursiveCharacterTextSplitter(
    chunk_size=800, chunk_overlap=150
).split_documents(docs)
db = Chroma.from_documents(chunks, OpenAIEmbeddings(model="text-embedding-3-small"))

# ONLINE: Retrieve + Generate
retriever = db.as_retriever(search_kwargs={"k": 4})
llm = ChatOpenAI(model="gpt-4o", temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", "Answer from context only. Cite sources.\n\nContext:\n{context}"),
    ("human", "{question}")
])

chain = (
    {"context": retriever | (lambda docs: "\n\n".join(d.page_content for d in docs)),
     "question": RunnablePassthrough()}
    | prompt | llm | StrOutputParser()
)

# Ask anything
print(chain.invoke("How do I authenticate with the Flight Offers API?"))
```

Output:

```text
To authenticate with the Flight Offers API, use OAuth 2.0
client credentials flow:

1. POST to /v1/security/oauth2/token with your API Key and Secret
2. Receive an access token (valid for 30 minutes)
3. Include as Bearer token in the Authorization header

[Source: flight-api-reference.pdf, Page: 12]
```

25 lines. From PDF to grounded, cited answers.

<DeepDive title="Chunk Overlap, Metadata Filtering, and MMR">

### Chunk Overlap

When you split text, information at the boundary gets cut. Overlap ensures continuity. Set overlap to 10-20% of chunk_size. Too much wastes storage and causes duplicate retrieval.

### Metadata Filtering

Narrow search space before vector similarity:

```python
# Search only flight docs, only version 2+
results = vector_store.similarity_search(
    "authentication flow",
    k=5,
    filter={
        "$and": [
            {"category": "api-reference"},
            {"version": {"$gte": "v2"}}
        ]
    }
)
```

Critical for multi-tenant RAG and large knowledge bases.

### MMR (Maximal Marginal Relevance)

Standard similarity search can return 5 chunks that all say the same thing. MMR balances relevance with diversity:

```python
results = vector_store.max_marginal_relevance_search(
    "flight search",
    k=5,
    fetch_k=20,       # fetch 20 candidates
    lambda_mult=0.7    # 0 = max diversity, 1 = max relevance
)
```

The algorithm: fetch top-20, select the most relevant one, then for each remaining slot pick the chunk that's most relevant to the query but most different from already-selected chunks. Eliminates redundancy.

</DeepDive>

## What to Take Away

Three things:

1. **Chunking is the highest-leverage decision.** Start with `RecursiveCharacterTextSplitter`, chunk_size 500-1000, overlap 100-200. Then benchmark and iterate.

2. **Hybrid retrieval beats pure semantic search.** Combine dense (meaning) with sparse (keywords). Production systems almost always use both.

3. **The prompt is your guardrail.** "Answer ONLY from context" is the single instruction that prevents hallucination in the generation step. Never skip it.
