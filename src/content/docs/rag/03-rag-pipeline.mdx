## Stage 2: Chunking — Ya Yapar Ya Kırar

RAG pipeline'ınızdaki en etkili tek karar. **Kötü chunking aşağıdaki her şeyi mahveder.** Harika retrieval, cümleyi ortasından bölen chunk'ları düzeltemez. Harika prompt'lar, üç alakasız konuyu karıştıran chunk'ları düzeltemez.

<KeyInsight>
Chunking retrieval kalitesini belirler. Retrieval kalitesi cevap kalitesini belirler. Bunu yanlış yaparsanız, aşağıdaki hiçbir şey kurtaramaz.
</KeyInsight>

Neden chunk'lıyoruz? Üç neden:
1. LLM'lerin context limiti var — tüm bilgi tabanını prompt'a tıkamazsınız
2. Embedding modelleri odaklı pasajlarda en iyi çalışır, 50 sayfalık dokümanlarda değil
3. Retrieval, daha küçük ve konu odaklı chunk'larla daha hassas

### Strategy 1: Recursive Character Splitting — Varsayılan

Önce doğal sınırları dener (paragraflar, sonra cümleler, sonra kelimeler), gerekirse daha küçük ayırıcılara düşer:

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
    separators=[
        "\n\n",    # First: paragraph breaks
        "\n",      # Then: line breaks
        ". ",      # Then: sentence endings
        ", ",      # Then: clause breaks
        " ",       # Then: word boundaries
        ""         # Last resort: character by character
    ]
)

chunks = splitter.split_documents(documents)
print(f"Created {len(chunks)} chunks from {len(documents)} documents")
```

**Başlangıç noktanız bu.** Kullanmamak için spesifik bir nedeniniz olana kadar bunu kullanın.

### Strategy 2: Semantic Chunking

Konu sınırlarını tespit etmek için embedding kullanır. Ardışık cümleler arası semantic similarity bir eşiğin altına düştüğünde böler:

```python
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings

splitter = SemanticChunker(
    embeddings=OpenAIEmbeddings(model="text-embedding-3-small"),
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=75
)

chunks = splitter.split_documents(documents)
# Chunks follow natural topic boundaries
```

**Pros**: Topically coherent chunks. **Cons**: Variable sizes, slower (requires embedding during indexing).

### Strategy 3: Document-Structure-Aware

Dokümanın kendi yapısını kullanır — başlıklar, bölümler — chunk'ları tanımlamak için:

```python
from langchain.text_splitter import MarkdownHeaderTextSplitter

headers_to_split_on = [
    ("#", "h1"),
    ("##", "h2"),
    ("###", "h3"),
]

splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=headers_to_split_on
)

# Each chunk inherits its header hierarchy as metadata
chunks = splitter.split_text(markdown_text)
# Headers: {'h1': 'Flight Offers API', 'h2': 'Search Endpoint'}
# Content: The search endpoint accepts origin, destination, and date...
```

**Ideal for**: Markdown docs, API references, structured manuals.

## Stage 3: Retrieval

Kullanıcı soru sorar. En ilgili chunk'ları bulmanız gerekir. Üç yaklaşım:

### Dense Retrieval (Semantic Search)

Sorguyu embed et, en yakın vektörleri bul. Module 2'de bunu kurmuştunuz:

```python
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector_store = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embeddings
)

retriever = vector_store.as_retriever(search_kwargs={"k": 5})
results = retriever.invoke("How do I authenticate with the Flight API?")
```

**Strength**: Understands meaning. "How do I log in?" matches docs about "authentication."
**Weakness**: Misses exact terms, codes, acronyms.

### Sparse Retrieval (BM25 / Keyword)

Geleneksel keyword search. Embedding yok. Anlam yok. Sadece terim eşleştirme:

```python
from langchain_community.retrievers import BM25Retriever

bm25_retriever = BM25Retriever.from_documents(chunks, k=5)
results = bm25_retriever.invoke("PNR AMAXTK error code 4812")
```

**Strength**: Exact term matching. Error codes, PNR locators, acronyms.
**Weakness**: "delayed flight" won't match "late arrival."

### Hybrid Retrieval — İkisinin İyisi

Production varsayılanı bu. Dense ve sparse'ı birleştir, sonuçları merge et:

```python
from langchain.retrievers import EnsembleRetriever

hybrid_retriever = EnsembleRetriever(
    retrievers=[
        vector_store.as_retriever(search_kwargs={"k": 5}),
        BM25Retriever.from_documents(chunks, k=5)
    ],
    weights=[0.5, 0.5]
)

results = hybrid_retriever.invoke("OAuth2 credentials for flight-offers v2")
# Finds results matching semantically AND by keyword
```

## Stage 4: Generation

İlgili chunk'larınız var. Şimdi dayanaklı bir cevap üretin.

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

llm = ChatOpenAI(model="gpt-4o", temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", """You are a travel technology support assistant.
Answer based ONLY on the provided context.
If the context doesn't contain the answer, say "I don't have enough information."

Rules:
- Be precise and technical
- Cite sources using [Source: filename, page X] format
- If sources conflict, mention the discrepancy

Context:
{context}"""),
    ("human", "{question}")
])

def format_context(docs):
    return "\n\n---\n\n".join([
        f"[Source: {doc.metadata.get('source', 'unknown')}, "
        f"Page: {doc.metadata.get('page', 'N/A')}]\n"
        f"{doc.page_content}"
        for doc in docs
    ])
```

### Full Pipeline — 25 Satır

Her şey bir arada:

```python
from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_chroma import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

# OFFLINE: Load, Chunk, Embed, Store
docs = PyPDFLoader("flight-api-guide.pdf").load()
chunks = RecursiveCharacterTextSplitter(
    chunk_size=800, chunk_overlap=150
).split_documents(docs)
db = Chroma.from_documents(chunks, OpenAIEmbeddings(model="text-embedding-3-small"))

# ONLINE: Retrieve + Generate
retriever = db.as_retriever(search_kwargs={"k": 4})
llm = ChatOpenAI(model="gpt-4o", temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", "Answer from context only. Cite sources.\n\nContext:\n{context}"),
    ("human", "{question}")
])

chain = (
    {"context": retriever | (lambda docs: "\n\n".join(d.page_content for d in docs)),
     "question": RunnablePassthrough()}
    | prompt | llm | StrOutputParser()
)

# Ask anything
print(chain.invoke("How do I authenticate with the Flight Offers API?"))
```

Output:

```text
To authenticate with the Flight Offers API, use OAuth 2.0
client credentials flow:

1. POST to /v1/security/oauth2/token with your API Key and Secret
2. Receive an access token (valid for 30 minutes)
3. Include as Bearer token in the Authorization header

[Source: flight-api-reference.pdf, Page: 12]
```

25 satır. PDF'ten dayanaklı, kaynaklı cevaplara.

## Quick Eval: Did Retrieval Work?

You've built a pipeline. Before moving on, ask the question every production RAG team asks every day: **how do we know if it's actually working?**

The simplest possible eval: write 3 test questions whose correct source document you already know, run retrieval, check if the right document is in the top-k results.

```python
# 3 test queries with known correct source documents
test_set = [
    {
        "question": "How do I authenticate against the Flight API?",
        "expected_source": "flight-api-reference.pdf",
    },
    {
        "question": "What's the cancellation policy for premium tickets?",
        "expected_source": "fare-rules-v3.pdf",
    },
    {
        "question": "How are PNR records structured?",
        "expected_source": "pnr-data-model.pdf",
    },
]

def did_retrieval_find_it(question: str, expected_source: str, k: int = 5) -> bool:
    """Returns True if expected document is in top-k retrieval results."""
    results = vector_store.similarity_search(question, k=k)
    sources = [doc.metadata.get("source", "") for doc in results]
    return any(expected_source in s for s in sources)

# Run the eval
hits = sum(
    did_retrieval_find_it(q["question"], q["expected_source"])
    for q in test_set
)
print(f"Retrieval recall: {hits}/{len(test_set)} ({hits / len(test_set):.0%})")
```

That's it. **Three questions, a binary metric, a single number.** It's the smallest possible RAG eval — and it's enough to tell you whether a chunking change made things better or worse.

<KeyInsight>
**You can't improve what you don't measure.** This 20-line eval is the difference between "I tweaked chunk_size and it feels better" and "I tweaked chunk_size and recall went from 33% to 100%". Module 5 expands this into RAGAS — but the principle is the same: known questions, known answers, count the hits.
</KeyInsight>

<DeepDive title="Chunk Overlap, Metadata Filtering, and MMR">

### Chunk Overlap

When you split text, information at the boundary gets cut. Overlap ensures continuity. Set overlap to 10-20% of chunk_size. Too much wastes storage and causes duplicate retrieval.

### Metadata Filtering

Narrow search space before vector similarity:

```python
# Search only flight docs, only version 2+
results = vector_store.similarity_search(
    "authentication flow",
    k=5,
    filter={
        "$and": [
            {"category": "api-reference"},
            {"version": {"$gte": "v2"}}
        ]
    }
)
```

Critical for multi-tenant RAG and large knowledge bases.

### MMR (Maximal Marginal Relevance)

Standard similarity search can return 5 chunks that all say the same thing. MMR balances relevance with diversity:

```python
results = vector_store.max_marginal_relevance_search(
    "flight search",
    k=5,
    fetch_k=20,       # fetch 20 candidates
    lambda_mult=0.7    # 0 = max diversity, 1 = max relevance
)
```

The algorithm: fetch top-20, select the most relevant one, then for each remaining slot pick the chunk that's most relevant to the query but most different from already-selected chunks. Eliminates redundancy.

</DeepDive>

## Özet

Üç şey:

1. **Chunking en yüksek kaldıraçlı karar.** `RecursiveCharacterTextSplitter`, chunk_size 500-1000, overlap 100-200 ile başlayın. Sonra benchmark yapıp iterasyon yapın.

2. **Hybrid retrieval saf semantic search'ü yener.** Dense (anlam) ile sparse'ı (keyword) birleştirin. Production sistemleri neredeyse her zaman ikisini kullanır.

3. **Prompt sizin guardrail'ınız.** "Answer ONLY from context" generation adımında hallucination'ı önleyen tek talimat. Asla atlamayın.
