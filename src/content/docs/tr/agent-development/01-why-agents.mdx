Kimse atamaz. Kimse önceliklendirir. Bir agent devreye girer:

1. Mesajı okur, temel sorunu çıkarır
2. Kod tabanını arar — `MealPreferenceService.cs`, satır 142'yi bulur
3. Hatayı tespit eder: APAC rota filtresi Tokyo'yu hariç tutuyor

5. Slack'e kök neden ve önerilen düzeltmeyle geri döner

Toplam süre: 14 saniye. Hiçbir insan dokunmadı.

**İşte bu bir agent.** Soruları yanıtlayan bir chatbot değil — algılayan, düşünen, harekete geçen ve bir hedefe otonom olarak ulaşan bir sistem.

<KeyInsight>
Agent, **sırada ne yapacağına** karar vermek için bir LLM kullanan ve sonra bunu gerçekten **yapan** yazılımdır. LLM beyindir. Araçlar ellerdir.
</KeyInsight>

## Chatbot ve Agent Karşılaştırması

Bu ayrım önemlidir çünkü neler geliştirebileceğinizi değiştirir.

| | Chatbot | Agent |
|---|---|---|
| **Etkileşim** | Siz sorarsınız, o yanıtlar | Siz bir hedef belirlersiniz, o hedefe doğru çalışır |
| **Eylemler** | Yalnızca metin üretir | API çağırır, dosya okur, veri yazar |
| **Bellek** | Turlar arasında unutur | Bağlamı hatırlar, sonuçlardan öğrenir |
| **Kontrol akışı** | İnsan her adımı yönlendirir | Agent sonraki adımlara otonom karar verir |
| **Örnek** | "Hava nasıl?" | "İptal edilen CDG uçuşundaki tüm yolcuları yeniden rezerve et" |

<PresenterNote>
Burada durun. Sorun: "Kaçınız ChatGPT veya Claude kullandınız?" Eller kalkar. "O bir chatbot. Siz sorarsınız, o cevaplar. Şimdi düşünün — ticket açabilse, veritabanı sorgulayabilse, email gönderebilse. İşte bugün yaptığımız sıçrama bu." [3.1-first-chain.ipynb](https://colab.research.google.com/github/kuthaygumus/build-with-ai/blob/main/public/notebooks/agent-dev/3.1-first-chain.ipynb) notebook'undaki chatbot vs chain karşılaştırmasını gösterin.
</PresenterNote>

Fark tek bir kelime: **agency** (özerklik). Ne yapacağına karar verebilme, yapabilme, sonucu gözlemleyebilme ve devam edebilme yeteneği.

```
Chatbot:  İnsan → Soru → LLM → Yanıt → bitti.

Agent:    İnsan → Hedef → LLM → [API çağırır] → [sonucu okur] → [sonraki adıma karar verir]
          → [başka API çağırır] → [değerlendirir] → ... → Hedefe ulaşıldı.
```

Her agent — framework, dil veya sağlayıcı fark etmeksizin — aynı döngüyü çalıştırır:

Bu, tüm eğitim boyunca sizi taşıyacak zihinsel model:

- **Algıla**: Agent girdi alır — bir kullanıcı mesajı, bir webhook, bir cron tetikleyicisi, bir dosya değişikliği. Ne olduğunu ayrıştırır.
- **Düşün**: LLM durumu değerlendirir. Hedef ne? Hangi araçlarım var? Sırada ne yapmalıyım? İşte zeka burada.
- **Harekete Geç**: Agent yürütür — API çağırır, veritabanı sorgular, dosya yazar, bildirim gönderir. Gerçek dünyaya dokunur.
- **Hatırla**: Agent ne olduğunu kaydeder. Konuşma geçmişi, araç sonuçları, alınan kararlar. Çok adımlı akıl yürütmeyi mümkün kılan budur.

Sonra döngü tekrarlar. Eylemin sonucunu algıla, sıradaki hakkında düşün, tekrar harekete geç. Tamamlanana kadar.

## Buraya Nasıl Geldik?

Dört dönem. Her biri öncekinin bir sınırlamasını çözdü:

<Tabs>
  <TabItem label="Kurallar (1970-2000)">
    ```python
    # You write every decision by hand
    if passenger.status == "delayed" and passenger.tier == "gold":
        rebook_to_next_available()
        send_lounge_voucher()
    ```
    
    Mükemmel çalışır... düşündüğünüz 50 durum için. 51. durum çöker. 1000 kural bakım yapılamaz hale gelir. Açıkça kodlamadığınız hiçbir şeyi işleyemez.

    **Sınırlama**: Ölçeklenmez. Yenilikle başa çıkamaz.
  </TabItem>

  <TabItem label="ML (2010'lar)">
    ```python
    # Learns patterns from historical data
    model = RandomForestClassifier()
    model.fit(past_rebookings, outcomes)
    action = model.predict(new_situation)
    ```
    
    Veriden öğrenir, karmaşıklıkla başa çıkar. Ama: görev başına bir model. Akıl yürütme yok. Nedenini açıklayamaz. Eğitilmediği görevleri işleyemez.

    **Sınırlama**: Dar kapsamlı. Bir model = bir görev. Akıl yürütme yok.
  </TabItem>

  <TabItem label="LLM'ler (2023)">
    ```python
    # Understands language, reasons about situations
    response = llm.chat("Passenger on delayed flight, Gold member, 
                         business class to Tokyo. What should we do?")
    ```
    
    Genel amaçlı akıl yürütme. Bağlamı anlar, belirsizlikle başa çıkar, kararları açıklar. Ama: sadece metin üretebilir. Aslında hiçbir şey *yapamaz*.

    **Sınırlama**: Akıllı ama güçsüz. Metin girer, metin çıkar.
  </TabItem>

  <TabItem label="Agent'lar (2024+)">
    ```python
    # LLM + tools + memory + autonomy
    agent = Agent(
        llm=claude,
        tools=[flight_api, booking_system, crm, email],
        memory=ConversationMemory()
    )
    agent.run("Handle rebooking for cancelled AF1234")
    ```
    
    Hem düşünür HEM harekete geçer. Çok adımlı iş akışları planlar. Araçları kullanır. Yeni durumlara uyum sağlar. Şu an buradayız.

    **Atılım**: LLM'e eller verin.
  </TabItem>
</Tabs>

<KeyInsight>
Her dönem bir sınırlamayı çözdü: kurallar ölçeklenemedi, ML akıl yürütemedi, LLM'ler harekete geçemedi. Agent'lar akıl yürütme + eylem'i birleştirir. Sıçrama budur.
</KeyInsight>

<DeepDive title="ReAct Kalıbı — Agent'lar Gerçekte Nasıl Düşünür">

**ReAct** (Reasoning + Acting — Akıl Yürütme + Eylem), modern agent'ların arkasındaki temel kalıptır. LLM düşünme ve yapma arasında gider gelir:

```
Question: Average delay for AF flights CDG→NRT this month?

Thought 1: I need flight data for this route and month.
Action 1: query_flights(carrier="AF", origin="CDG", dest="NRT", month="2026-09")
Observation 1: [28 flights returned with delay data]

Thought 2: Now calculate the average delay.
Action 2: calculate(sum(delays) / count(flights))  
Observation 2: 23.4 minutes

Thought 3: Is this above or below normal? Let me check.
Action 3: get_baseline(route="CDG-NRT", season="fall")
Observation 3: Seasonal average: 18.2 minutes

Answer: 23.4 min average, 28.6% above seasonal norm of 18.2 min.
```

Bu neden önemli:
- **Şeffaf**: Her akıl yürütme adımını denetleyebilirsiniz
- **Temelli**: Eylemler gerçek veri sağlar, halüsinasyonu azaltır  
- **Kontrol edilebilir**: Akıl yürütme raydan çıkarsa müdahale edebilirsiniz

Bu tam olarak LangChain ve LangGraph'ın arka planda uyguladığı şeydir — bu kalıbı Modül 3 ve 4'te göreceksiniz.

</DeepDive>

<DeepDive title="Araç Kullanımı — LLM'ler Fonksiyonları Nasıl Çağırır">

Modern LLM'ler sadece metin üretmez — yapılandırılmış **araç çağrıları** üretir:

```json
{
    "tool": "search_flights",
    "arguments": {
        "origin": "CDG",
        "destination": "NRT", 
        "date": "2026-09-15"
    }
}
```

Agent framework'ü:
1. Kullanıcı mesajı + araç tanımlarını LLM'e gönderir
2. LLM bir araç çağrısı (veya doğrudan yanıt) çıktılar
3. Framework aracı yürütür
4. Sonuç LLM'e geri gider
5. LLM karar verir: yanıtla mı, yoksa başka bir araç çağır mı?

Bu, Claude, GPT-4 ve Gemini'de doğal bir yetenektir. Öğreneceğimiz framework'ler orkestrasyon katmanını sağlar.

</DeepDive>

## Çıkarımlar

Üç şey:

1. **Agent = LLM + araçlar + bellek + döngü.** LLM düşünür, araçlar harekete geçer, bellek kalıcıdır, döngü hedefe ulaşılana kadar devam eder.

2. **İnsan-döngüde üretim kalıbıdır.** Tam özerklik kulağa havalı gelir ama nadiren hedeftir. Agent'lar hacmi üstlenir; insanlar muhakemeyi üstlenir.

3. **Spektrumda soldan sağa ilerliyoruz.** Tek araç çağrısı → chain → router → çoklu agent. 2. Günün sonunda tam halini geliştireceksiniz.
