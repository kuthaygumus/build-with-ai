## LLM'ler Kurumsal Bilgide Neden Başarısız Olur

LLM'lerin üç temel kör noktası vardır. Her biri kurumsal kullanım için engeldir. RAG üçünü de çözer.

### 1. Halüsinasyon

LLM'ler bir şeyi "bilmez". Sonraki token'ı tahmin ederler. Eğitim verisi bir konuda yetersiz olduğunda, boşluğu makul görünen kurguyla doldururlar.

```python
# Ask about a specific Flight API version
response = llm("What are the parameters for the FlightOffers v4 API?")
# The LLM will confidently describe parameters that don't exist,
# mixing real v2 params with invented ones.
# It doesn't know the difference. It can't.
```

### 2. Eskimiş Bilgi

Her modelin bir eğitim kesim tarihi vardır. Dünya ilerlemeye devam eder. Model ise etmez.

Dahili belgeleriniz her gün değişir. Yeniden eğitim GPU-haftaları ve altı haneli maliyetler gerektirir. Bu bir iş akışı değil -- bir krizdir.

### 3. Özel Verilere Sıfır Erişim

Bu bir model kalitesi sorunu değildir. GPT-5 bunu çözmeyecek. Claude 4 bunu çözmeyecek. **Bu bir mimari sorunudur.** RAG mimari çözümdür.

## RAG Nedir -- 30 Saniyede

**Retrieval-Augmented Generation (Erişimle Güçlendirilmiş Üretim).** Modelin eğitimden "hatırladığı" bilgilere güvenmek yerine, ilgili belgeleri alıp prompt'a enjekte edersiniz.

Model belgelerinizi okur, sonra yanıtlar. Her seferinde. Güncel veri. Kaynak gösterimli.

Kilit nokta: **LLM tüm bilgi tabanınızı asla görmez.** Yalnızca en ilgili birkaç chunk'ı, soruyla birlikte enjekte edilmiş olarak görür.

```python
# RAG in 10 lines of pseudocode
def rag_answer(question: str) -> str:
    # 1. Find relevant documents
    relevant_docs = vector_store.similarity_search(question, k=5)

    # 2. Build prompt with context
    context = "\n\n".join([doc.page_content for doc in relevant_docs])
    prompt = f"""Answer based ONLY on this context. If unsure, say so.

Context:
{context}

Question: {question}"""

    # 3. Generate grounded answer
    return llm.invoke(prompt)
```

## RAG vs Fine-Tuning

Bu herkesin sorduğu sorudur. İşte karar noktası:

| | RAG | Fine-Tuning |
|---|---|---|
| **Amaç** | Modelin bir şeyi **bilmesi** gerekiyor | Modelin farklı **davranması** gerekiyor |
| **Veri güncelliği** | Gerçek zamanlı (istediğiniz zaman yeniden indeksleyin) | Eskir (yeniden eğitim gerektirir) |
| **Kaynak gösterimi** | Yerleşik (hangi belgeden geldiğini bilirsiniz) | Mümkün değil |
| **Maliyet** | Düşük (embedding + depolama) | Yüksek (GPU saatleri) |
| **Halüsinasyon kontrolü** | Güçlü (kaynaklara dayalı) | Zayıf (hâlâ serbestçe üretir) |
| **En uygun olduğu alan** | Bilgi erişimi, Soru-Cevap, arama | Ton, format, alan dili |

<KeyInsight>
Modelin bir şeyi **bilmesi** gerektiğinde RAG kullanın. Modelin farklı **davranması** gerektiğinde fine-tuning kullanın. Canlı ortamda genellikle ikisini birden kullanırsınız.
</KeyInsight>

## İndeksleme Aşaması -- Sorgulardan Önce Ne Olur

RAG herhangi bir şeyi yanıtlayabilmeden önce, bilgi tabanınızı hazırlarsınız. Bu çevrimdışı olarak bir kez yapılır:

<FlowDiagram title="Çevrimdışı İndeksleme Pipeline'ı">
  <div class="flow-row">
    <div class="flow-node secondary">
      <span class="node-icon">📄</span>
      <span class="node-label">Yükle</span>
      <span class="node-desc">PDF, web, markdown, API</span>
    </div>
    <div class="flow-arrow animated">→</div>
    <div class="flow-node secondary">
      <span class="node-icon">✂️</span>
      <span class="node-label">Chunk'la</span>
      <span class="node-desc">Odaklı parçalara böl</span>
    </div>
    <div class="flow-arrow animated">→</div>
    <div class="flow-node secondary">
      <span class="node-icon">🧮</span>
      <span class="node-label">Embedding Oluştur</span>
      <span class="node-desc">Metni vektörlere dönüştür</span>
    </div>
    <div class="flow-arrow animated">→</div>
    <div class="flow-node success">
      <span class="node-icon">💾</span>
      <span class="node-label">Depola</span>
      <span class="node-desc">Vektör veritabanına kaydet</span>
    </div>
  </div>
</FlowDiagram>

```python
from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

# 1. Load
docs = PyPDFLoader("flight-api-guide.pdf").load()

# 2. Chunk
chunks = RecursiveCharacterTextSplitter(
    chunk_size=1000, chunk_overlap=200
).split_documents(docs)

# 3. Embed + Store
vector_store = Chroma.from_documents(
    documents=chunks,
    embedding=OpenAIEmbeddings(model="text-embedding-3-small"),
    persist_directory="./chroma_db"
)

print(f"Indexed {len(chunks)} chunks from {len(docs)} pages")
```

Gelecek modüllerde her adıma derinlemesine dalacağız. Şimdilik akışı hatırlayın: **Yükle, Chunk'la, Embedding Oluştur, Depola.**

<DeepDive title="RAG'ın Akademik Kökenleri">

RAG, 2020 yılında Facebook AI Research'teki Patrick Lewis ve arkadaşları tarafından yayımlanan **"Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks"** makalesinde tanıtılmıştır.

Temel katkı: önceden eğitilmiş bir seq2seq modeli (BART) ile yoğun bir retriever'ı (DPR) birleştirip uçtan uca eğitmek. Retriever ve generator, neyin erişileceğini ve nasıl üretileceğini ortaklaşa optimize eder.

Modern RAG önemli ölçüde ayrışmıştır. Günümüz sistemleri donmuş LLM'ler (uçtan uca eğitim yok), FAISS yerine vektör veritabanları ve fine-tuned generator'lar yerine prompt mühendisliği kullanır. "RAG" terimi, belirli bir mimariden bir **tasarım kalıbına** evrilmiştir -- üretimi güçlendirmek için harici bilgi erişen herhangi bir sistem.

**RAG soy ağacındaki önemli makaleler:**
1. **DPR** (Karpukhin ve ark., 2020) -- Dense Passage Retrieval
2. **RAG** (Lewis ve ark., 2020) -- Orijinal makale
3. **RETRO** (Borgeaud ve ark., 2022) -- Ölçekte retrieval ile güçlendirilmiş transformer'lar
4. **Self-RAG** (Asai ve ark., 2023) -- LLM ne zaman erişeceğine kendisi karar verir
5. **CRAG** (Yan ve ark., 2024) -- Erişim değerlendirmeli Düzeltici RAG

</DeepDive>

## Önemli Çıkarımlar

Üç şey:

1. **LLM'lerin üç kör noktası vardır** -- halüsinasyon, eskimiş bilgi, özel veriye erişim yok. RAG üçünü de modeli değiştirmeden, girdiyi değiştirerek düzeltir.

2. **RAG = eriş, sonra üret.** İlgili belgeleri bul, prompt'a enjekte et, modelin kanıta dayalı yanıt vermesini sağla. Basit konsept, güçlü sonuçlar.

3. **RAG vs fine-tuning bir yarış değildir.** RAG bilgi içindir. Fine-tuning davranış içindir. Hangi sorunu çözdüğünüzü bilin.
