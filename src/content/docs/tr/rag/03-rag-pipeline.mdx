## Aşama 2: Chunking -- Belirleyici Karar

Bu, RAG pipeline'ınızdaki en etkili tek karardır. **Kötü chunking her şeyi mahveder.** Mükemmel retrieval, cümleleri düşüncenin ortasından bölen chunk'ları düzeltemez. Mükemmel prompt'lar, üç alakasız konuyu karıştıran chunk'ları düzeltemez.

<KeyInsight>
Chunking, retrieval kalitesini belirler. Retrieval kalitesi, yanıt kalitesini belirler. Bunu yanlış yaparsanız, sonrasında hiçbir şey sizi kurtaramaz.
</KeyInsight>

Neden chunk'lıyoruz? Üç nedeni var:
1. LLM'lerin bağlam sınırları vardır -- tüm bilgi tabanını prompt'a tıkamazsınız
2. Embedding modelleri 50 sayfalık belgeler yerine odaklı pasajlarda en iyi çalışır
3. Daha küçük, konusal olarak tutarlı chunk'larla retrieval daha hassas olur

<PresenterNote>
[3.1-rag-pipeline.ipynb](https://colab.research.google.com/github/kuthaygumus/build-with-ai/blob/main/public/notebooks/rag/3.1-rag-pipeline.ipynb) notebook'undaki chunking karşılaştırma hücrelerini çalıştırın. Tüm dokümanı embed etme vs paragraf paragraf embed etme farkını gösterin. Full-document embedding her şeyle zayıf eşleşir, paragraf embedding doğru paragrafla güçlü eşleşir. Sorun: "chunk_size=2000 ile chunk_size=500 arasındaki fark ne olur?" Notebook'ta deneyin.
</PresenterNote>

### Strateji 1: Özyinelemeli Karakter Bölme -- Varsayılan

Önce doğal sınırları dener (paragraflar, sonra cümleler, sonra kelimeler), gerektiğinde daha küçük ayırıcılara geri döner:

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
    separators=[
        "\n\n",    # First: paragraph breaks
        "\n",      # Then: line breaks
        ". ",      # Then: sentence endings
        ", ",      # Then: clause breaks
        " ",       # Then: word boundaries
        ""         # Last resort: character by character
    ]
)

chunks = splitter.split_documents(documents)
print(f"Created {len(chunks)} chunks from {len(documents)} documents")
```

**Bu başlangıç noktanızdır.** Kullanmamak için özel bir nedeniniz olana kadar bunu kullanın.

### Strateji 2: Semantik Chunking

Konu sınırlarını tespit etmek için embedding'leri kullanır. Ardışık cümleler arasındaki semantik benzerlik bir eşiğin altına düştüğünde böler:

```python
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings

splitter = SemanticChunker(
    embeddings=OpenAIEmbeddings(model="text-embedding-3-small"),
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=75
)

chunks = splitter.split_documents(documents)
# Chunks follow natural topic boundaries
```

**Artılar**: Konusal olarak tutarlı chunk'lar. **Eksiler**: Değişken boyutlar, daha yavaş (indeksleme sırasında embedding gerektirir).

### Strateji 3: Belge Yapısına Duyarlı

Belgenin kendi yapısını -- başlıklar, bölümler -- chunk'ları tanımlamak için kullanır:

```python
from langchain.text_splitter import MarkdownHeaderTextSplitter

headers_to_split_on = [
    ("#", "h1"),
    ("##", "h2"),
    ("###", "h3"),
]

splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=headers_to_split_on
)

# Each chunk inherits its header hierarchy as metadata
chunks = splitter.split_text(markdown_text)
# Headers: {'h1': 'Flight Offers API', 'h2': 'Search Endpoint'}
# Content: The search endpoint accepts origin, destination, and date...
```

**İdeal kullanım alanı**: Markdown belgeler, API referansları, yapılandırılmış kılavuzlar.

## Aşama 3: Retrieval

Kullanıcı bir soru sorar. En ilgili chunk'ları bulmanız gerekir. Üç yaklaşım:

### Dense Retrieval (Semantik Arama)

Sorguyu embedding'leyin, en yakın vektörleri bulun. Bu, Modül 2'de oluşturduğunuz şeydir:

```python
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector_store = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embeddings
)

retriever = vector_store.as_retriever(search_kwargs={"k": 5})
results = retriever.invoke("How do I authenticate with the Flight API?")
```

**Güçlü yanı**: Anlamı kavrar. "How do I log in?" ifadesi "authentication" hakkındaki belgelerle eşleşir.
**Zayıf yanı**: Tam terimleri, kodları, kısaltmaları kaçırır.

### Sparse Retrieval (BM25 / Anahtar Kelime)

Geleneksel anahtar kelime araması. Embedding yok. Anlam yok. Yalnızca terim eşleştirme:

```python
from langchain_community.retrievers import BM25Retriever

bm25_retriever = BM25Retriever.from_documents(chunks, k=5)
results = bm25_retriever.invoke("PNR AMAXTK error code 4812")
```

**Güçlü yanı**: Tam terim eşleştirme. Hata kodları, PNR locator'ları, kısaltmalar.
**Zayıf yanı**: "delayed flight" ifadesi "late arrival" ile eşleşmez.

### Hibrit Retrieval -- Her İkisinin En İyisi

Bu prodüksiyon varsayılanıdır. Dense ve sparse'ı birleştirin, sonuçları birleştirin:

```python
from langchain.retrievers import EnsembleRetriever

hybrid_retriever = EnsembleRetriever(
    retrievers=[
        vector_store.as_retriever(search_kwargs={"k": 5}),
        BM25Retriever.from_documents(chunks, k=5)
    ],
    weights=[0.5, 0.5]
)

results = hybrid_retriever.invoke("OAuth2 credentials for flight-offers v2")
# Finds results matching semantically AND by keyword
```

## Aşama 4: Üretim (Generation)

İlgili chunk'larınız var. Şimdi dayanaklı bir yanıt üretin.

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

llm = ChatOpenAI(model="gpt-4o", temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", """You are a travel technology support assistant.
Answer based ONLY on the provided context.
If the context doesn't contain the answer, say "I don't have enough information."

Rules:
- Be precise and technical
- Cite sources using [Source: filename, page X] format
- If sources conflict, mention the discrepancy

Context:
{context}"""),
    ("human", "{question}")
])

def format_context(docs):
    return "\n\n---\n\n".join([
        f"[Source: {doc.metadata.get('source', 'unknown')}, "
        f"Page: {doc.metadata.get('page', 'N/A')}]\n"
        f"{doc.page_content}"
        for doc in docs
    ])
```

### Tam Pipeline -- 25 Satır

Her şey bir arada:

```python
from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_chroma import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

# OFFLINE: Load, Chunk, Embed, Store
docs = PyPDFLoader("flight-api-guide.pdf").load()
chunks = RecursiveCharacterTextSplitter(
    chunk_size=800, chunk_overlap=150
).split_documents(docs)
db = Chroma.from_documents(chunks, OpenAIEmbeddings(model="text-embedding-3-small"))

# ONLINE: Retrieve + Generate
retriever = db.as_retriever(search_kwargs={"k": 4})
llm = ChatOpenAI(model="gpt-4o", temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", "Answer from context only. Cite sources.\n\nContext:\n{context}"),
    ("human", "{question}")
])

chain = (
    {"context": retriever | (lambda docs: "\n\n".join(d.page_content for d in docs)),
     "question": RunnablePassthrough()}
    | prompt | llm | StrOutputParser()
)

# Ask anything
print(chain.invoke("How do I authenticate with the Flight Offers API?"))
```

Çıktı:

```text
To authenticate with the Flight Offers API, use OAuth 2.0
client credentials flow:

1. POST to /v1/security/oauth2/token with your API Key and Secret
2. Receive an access token (valid for 30 minutes)
3. Include as Bearer token in the Authorization header

[Source: flight-api-reference.pdf, Page: 12]
```

25 satır. PDF'den dayanaklı, kaynak gösterimli yanıtlara.

## Hızlı Eval: Retrieval Çalıştı mı?

Bir pipeline kurdunuz. Devam etmeden önce, her production RAG ekibinin her gün sorduğu soruyu sorun: **gerçekten çalışıp çalışmadığını nasıl bileceğiz?**

Mümkün olan en basit eval: doğru kaynak dokümanını zaten bildiğiniz 3 test sorusu yazın, retrieval'ı çalıştırın, doğru dokümanın top-k sonuçlarda olup olmadığını kontrol edin.

```python
# Doğru kaynak dokümanları bilinen 3 test sorgusu
test_set = [
    {
        "question": "Flight API'ye karşı nasıl authenticate ediyorum?",
        "expected_source": "flight-api-reference.pdf",
    },
    {
        "question": "Premium biletler için iptal politikası nedir?",
        "expected_source": "fare-rules-v3.pdf",
    },
    {
        "question": "PNR kayıtları nasıl yapılandırılır?",
        "expected_source": "pnr-data-model.pdf",
    },
]

def did_retrieval_find_it(question: str, expected_source: str, k: int = 5) -> bool:
    """Beklenen doküman top-k retrieval sonuçlarındaysa True döner."""
    results = vector_store.similarity_search(question, k=k)
    sources = [doc.metadata.get("source", "") for doc in results]
    return any(expected_source in s for s in sources)

# Eval'i çalıştır
hits = sum(
    did_retrieval_find_it(q["question"], q["expected_source"])
    for q in test_set
)
print(f"Retrieval recall: {hits}/{len(test_set)} ({hits / len(test_set):.0%})")
```

İşte bu kadar. **Üç soru, ikili bir metric, tek bir sayı.** Mümkün olan en küçük RAG eval — ve bir chunking değişikliğinin işleri daha iyi mi yoksa daha kötü mü yaptığını söylemek için yeterli.

<KeyInsight>
**Ölçemediğiniz şeyi iyileştiremezsiniz.** Bu 20 satırlık eval, "chunk_size'ı değiştirdim, daha iyi hissettim" ile "chunk_size'ı değiştirdim, recall %33'ten %100'e çıktı" arasındaki farktır. Modül 5 bunu RAGAS'a genişletir — ama prensip aynı: bilinen sorular, bilinen cevaplar, hit'leri say.
</KeyInsight>

<DeepDive title="Chunk Overlap, Meta Veri Filtreleme ve MMR">

### Chunk Overlap

Metni böldüğünüzde, sınırdaki bilgiler kesilir. Overlap süreklilik sağlar. Overlap'i chunk_size'ın %10-20'si olarak ayarlayın. Çok fazlası depolamayı israf eder ve tekrarlı retrieval'a neden olur.

### Meta Veri Filtreleme

Vektör benzerliğinden önce arama alanını daraltın:

```python
# Search only flight docs, only version 2+
results = vector_store.similarity_search(
    "authentication flow",
    k=5,
    filter={
        "$and": [
            {"category": "api-reference"},
            {"version": {"$gte": "v2"}}
        ]
    }
)
```

Çok kiracılı RAG ve büyük bilgi tabanları için kritik öneme sahiptir.

### MMR (Maximal Marginal Relevance)

Standart benzerlik araması, hepsi aynı şeyi söyleyen 5 chunk döndürebilir. MMR, ilgililik ile çeşitliliği dengeler:

```python
results = vector_store.max_marginal_relevance_search(
    "flight search",
    k=5,
    fetch_k=20,       # fetch 20 candidates
    lambda_mult=0.7    # 0 = max diversity, 1 = max relevance
```

## Önemli Çıkarımlar

Üç şey:

1. **Chunking en yüksek kaldıraçlı karardır.** `RecursiveCharacterTextSplitter`, chunk_size 500-1000, overlap 100-200 ile başlayın. Sonra karşılaştırmalı test yapın ve iyileştirin.

2. **Hibrit retrieval saf semantik aramayı geçer.** Dense (anlam) ile sparse (anahtar kelime) birleştirin. Prodüksiyon sistemleri neredeyse her zaman ikisini birden kullanır.

3. **Prompt güvenlik bariyerinizdir.** "YALNIZCA bağlama dayanarak yanıtla" ifadesi, üretim aşamasında halüsinasyonu önleyen tek talimattır. Asla atlamayın.
