### Başarısızlık 1: Sorgu-Belge Uyumsuzluğu

Kullanıcı günlük dilde sorar. Belgeler teknik. Aralarındaki semantik benzerlik düşüktür -- belge yanıtı içerse bile.

```text
User query:   "Why is my booking not showing up?"
Document:     "The PNR retrieval endpoint returns 404 when the record
               locator has expired or when the booking was created in
               a different office ID context."

Problem: casual language vs. technical documentation.
The embedding vectors are far apart. The right doc isn't retrieved.
```

### Başarısızlık 2: İlgili Ama Gömülü

Retriever doğru belgeyi bulur -- ama 8. sırada. Pipeline'ınız LLM'e yalnızca ilk 5'i gönderir:

```text
Rank 1: [0.82] General booking API overview      ← too broad
Rank 2: [0.81] Flight booking creation guide      ← wrong topic
...
Rank 8: [0.72] PNR retrieval troubleshooting      ← THIS IS THE ANSWER
```

### Başarısızlık 3: Yanıt Birden Fazla Belgeye Yayılıyor

Yanıt üç belge gerektirir. Basit RAG ikisini bulur, üçüncüyü kaçırır. Yanıt eksik -- ya da daha kötüsü, yanlıştır:

```text
Query: "Can I change my flight after check-in?"

Doc A: "Changes allowed up to 24h before departure."
Doc B: "Check-in opens 24h before departure."
Doc C: "Post-check-in changes require cancellation and rebooking."

Naive RAG finds A and B, misses C.
Answer: "Yes, changes are allowed up to 24h before." — WRONG.
```

```python
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm = ChatOpenAI(model="gpt-4o", temperature=0)

# Step 1: Generate a hypothetical answer
hyde_prompt = ChatPromptTemplate.from_messages([
    ("system", """Write a short passage that would answer this question.
Write it as if it comes from official technical documentation.
It doesn't need to be factually correct — just plausible."""),
    ("human", "{question}")
])

hyde_chain = hyde_prompt | llm | StrOutputParser()

question = "Why is my booking not showing up?"
hypothetical_doc = hyde_chain.invoke({"question": question})
# "Bookings may not appear in retrieval results when the PNR has expired,
#  when the office ID context differs, or when the booking is pending
#  ticketing confirmation."
```

```python
# Step 2: Search with the hypothetical doc, not the question
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
hyde_embedding = embeddings.embed_query(hypothetical_doc)
results = vector_store.similarity_search_by_vector(hyde_embedding, k=5)
```

Bu neden işe yarar: varsayımsal belge gerçek belgelerle **aynı sözcük dağarcığını** kullanır. "PNR expired" ifadesi, "PNR retrieval returns 404" ile "booking not showing up"tan çok daha iyi eşleşir.

### Multi-Query

Daha geniş bir retrieval ağı oluşturmak için aynı sorunun birden fazla perspektifini üretin:

```python
multi_query_prompt = ChatPromptTemplate.from_messages([
    ("system", """Generate 3 alternative versions of this question
that capture different aspects or phrasings. One per line."""),
    ("human", "{question}")
])

question = "Why is my booking not showing up?"
alternatives = (multi_query_prompt | llm | StrOutputParser()).invoke(
    {"question": question}
)
# 1. What causes a PNR to not appear in booking retrieval?
# 2. Troubleshooting missing reservations in the booking system
# 3. How to resolve 404 errors when fetching booking records?

# Retrieve for each variant, deduplicate results
all_results = []
for q in [question] + alternatives.strip().split("\n"):
    all_results.extend(retriever.invoke(q))

unique_results = list({doc.page_content: doc for doc in all_results}.values())
```

### Step-Back Prompting

Önce daha geniş bir soru sorun, bu bağlamı kullanarak belirli soruyu yanıtlayın:

```python
step_back_prompt = ChatPromptTemplate.from_messages([
    ("system", """Generate a broader question that provides context
for answering the original. Example:
Specific: "Why does error 4812 occur?"
Broader: "What are common errors in Flight Offers Search and their causes?"
Return only the broader question."""),
    ("human", "{question}")
])

broad_question = (step_back_prompt | llm | StrOutputParser()).invoke(
    {"question": "Why does my PNR expire after 24 hours?"}
)
# "What is the PNR lifecycle and what determines expiration policies?"

# Retrieve for both broad and specific, combine
broad_context = retriever.invoke(broad_question)
specific_context = retriever.invoke(question)
combined = broad_context + specific_context
```

### Hangisini Ne Zaman Kullanmalı

| Teknik | En Uygun Kullanım | Maliyet | Gecikme |
|--------|-------------------|---------|---------|
| **HyDE** | Teknik belgeler, sözcük dağarcığı uyumsuzluğu | 1 LLM çağrısı | +1-2sn |
| **Multi-Query** | Belirsiz veya geniş sorular | 1 LLM çağrısı | +1-2sn |
| **Step-Back** | Daha geniş bağlam gerektiren spesifik sorular | 1 LLM çağrısı + 2x retrieval | +2-3sn |

<Aside type="tip">
Bunları birleştirebilirsiniz. Varyantlar üretmek için Multi-Query kullanın, sonra her birine HyDE uygulayın. Pahalı ama kritik uygulamalar için güçlüdür.
</Aside>

## Çözüm 2: Re-Ranking

Retrieval size adayları verir. Re-ranking onları **hassasiyete göre yeniden sıralar.**

Kalıp: hızlı bir bi-encoder ile geniş kapsamlı erişim yapın, sonra yavaş bir cross-encoder ile hassas şekilde yeniden sıralayın.

    <div class="flow-node success">
      <span class="node-icon">✅</span>

Fark: bi-encoder'lar sorgu ve belgeyi **ayrı ayrı** embedding'ler (hızlı, ama yaklaşık). Cross-encoder'lar sorgu ve belgeyi **birlikte** işler (yavaş, ama hassas -- her iki metindeki her kelimenin etkileşimini görür).

### Cohere Reranker ile

```python
from langchain_cohere import CohereRerank
from langchain.retrievers import ContextualCompressionRetriever

# Retrieve 20 candidates broadly
base_retriever = vector_store.as_retriever(search_kwargs={"k": 20})

# Re-rank to top 5 precisely
reranker = CohereRerank(model="rerank-english-v3.0", top_n=5)

reranking_retriever = ContextualCompressionRetriever(
    base_compressor=reranker,
    base_retriever=base_retriever
)

results = reranking_retriever.invoke("How to handle expired PNRs?")
```

### Açık Kaynak Alternatif

```python
from sentence_transformers import CrossEncoder

cross_encoder = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")

# Score each candidate against the query
candidates = vector_store.similarity_search("expired PNR handling", k=20)
pairs = [("How to handle expired PNRs?", doc.page_content) for doc in candidates]
scores = cross_encoder.predict(pairs)

# Sort by cross-encoder score
ranked = sorted(zip(scores, candidates), key=lambda x: x[0], reverse=True)
top_5 = [doc for _, doc in ranked[:5]]
```

<Aside type="note">
Re-ranking genellikle standart karşılaştırmalarda yanıt kalitesini **%10-25** artırır. Ekleyebileceğiniz en yüksek yatırım getirili iyileştirmelerden biridir -- ve yaklaşık 10 satır kod gerektirir.
</Aside>

## Çözüm 3: Agentic RAG (Kavramsal)

Burası RAG'ın Bölüm 1'deki Agent eğitimiyle buluştuğu noktadır. Basit RAG'da retrieval **her zaman ve tam olarak bir kez** gerçekleşir. Agentic RAG bir agent'a şunlara karar verme yetkisi tanır:

- Erişim yapıp **yapmayacağı**? (belki yanıt zaten biliniyor — selamlama, matematik, genel bilgi)
- **Ne** arayacağı? (şimdiye kadar bulduklarına göre sorguyu yeniden formüle et)
- **Tekrar arayıp aramayacağı**? (ilk retrieval yeterli değilse, max 3 iterasyon)

### Pattern 10 satır pseudocode'da

```text
def agentic_rag(question):
    # 1. Aramaya gerek var mı?
    if not agent.needs_retrieval(question):
        return llm.answer(question)              # direkt cevap

    # 2. Yeterli context bulana kadar iteratif arama
    context = []
    for attempt in range(MAX_ITERATIONS=3):
        results = retriever.search(question)
        context.extend(results)
        if agent.is_context_sufficient(question, context):
            break
        question = agent.reformulate(question, context)

    # 3. Kanıta dayalı cevabı üret
    return llm.answer(question, context)
```

Fikrin tamamı bu. Üç karar, hepsi router rolündeki bir LLM tarafından veriliyor: "ara?", "yeterli mi?", "yeniden formüle?". Tam LangGraph implementasyonu (≈60 satır Python) bu modülün sonundaki DeepDive'da — canlı workshop için fazla yoğun, eğitim sonrası self-study için ideal.

<KeyInsight>
**Bugün Agentic RAG kodunu ezberlemenize gerek yok.** **Karar noktalarını** ezberleyin: aramalı mıyım, yeterli mi, yeniden formüle etmeli miyim. Production'da inşa etmeniz gerektiğinde, Agent Development eğitimindeki LangGraph pattern'ları tanıdık gelecek — orada gördüğünüz aynı state + conditional routing'in aynısı.
</KeyInsight>

<DeepDive title="İleri Düzey: Agentic RAG — Tam LangGraph İmplementasyonu">

Yukarıdaki kavramsal pseudocode, bu LangGraph implementasyonuna genişler. Workshop sonrası okuyun — Agent Development eğitiminin LangGraph modülünde gördüğünüz aynı conditional-routing pattern, sadece retrieval kararlarına uygulanmış halde.

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage

class AgentState(TypedDict):
    question: str
    context: list[str]
    answer: str
    needs_retrieval: bool
    retrieval_count: int

llm = ChatGroq(model="llama-3.3-70b-versatile", temperature=0)

def should_retrieve(state: AgentState) -> AgentState:
    """Agent decides if retrieval is needed."""
    response = llm.invoke([
        SystemMessage(content="""Decide if you need to search a knowledge base.
Reply YES or NO only.
NO for: greetings, general knowledge, math.
YES for: specific product questions, policy lookups, technical details."""),
        HumanMessage(content=state["question"])
    ])
    state["needs_retrieval"] = "YES" in response.content.upper()
    return state

def retrieve(state: AgentState) -> AgentState:
    """Retrieve relevant documents."""
    results = retriever.invoke(state["question"])
    state["context"] = [doc.page_content for doc in results]
    state["retrieval_count"] = state.get("retrieval_count", 0) + 1
    return state

def evaluate_context(state: AgentState) -> str:
    """Is the context sufficient?"""
    if state["retrieval_count"] >= 3:
        return "generate"  # prevent infinite loops

    response = llm.invoke([
        SystemMessage(content="Does this context answer the question? YES or NO."),
        HumanMessage(content=f"Q: {state['question']}\nContext: {state['context']}")
    ])
    return "generate" if "YES" in response.content.upper() else "retrieve_more"

def retrieve_more(state: AgentState) -> AgentState:
    """Reformulate and retrieve again."""
    response = llm.invoke([
        SystemMessage(content="Reformulate the question to find missing details."),
        HumanMessage(content=f"Original: {state['question']}\nFound: {state['context']}")
    ])
    state["question"] = response.content
    return retrieve(state)

def generate(state: AgentState) -> AgentState:
    """Generate final answer."""
    context = "\n\n".join(state["context"]) if state["context"] else "No context."
    response = llm.invoke([
        SystemMessage(content=f"Answer from context. Cite sources.\n\n{context}"),
        HumanMessage(content=state["question"])
    ])
    state["answer"] = response.content
    return state

# Build the graph
def route_retrieval(state: AgentState) -> str:
    return "retrieve" if state["needs_retrieval"] else "direct_answer"

graph = StateGraph(AgentState)
graph.add_node("should_retrieve", should_retrieve)
graph.add_node("retrieve", retrieve)
graph.add_node("evaluate", lambda s: s)
graph.add_node("retrieve_more", retrieve_more)
graph.add_node("generate", generate)
graph.add_node("direct_answer", lambda s: {**s, "answer": llm.invoke(
    [HumanMessage(content=s["question"])]).content})

graph.set_entry_point("should_retrieve")
graph.add_conditional_edges("should_retrieve", route_retrieval)
graph.add_edge("retrieve", "evaluate")
graph.add_conditional_edges("evaluate", evaluate_context, {
    "generate": "generate",
    "retrieve_more": "retrieve_more"
})
graph.add_edge("retrieve_more", "evaluate")
graph.add_edge("generate", END)
graph.add_edge("direct_answer", END)

agent = graph.compile()
```

İlginç tasarım kararları:

1. **`should_retrieve` standalone bir node** — her sorgu veritabanına ihtiyaç duymaz. Selamlamalar, matematik ve genel bilgi LLM tarafından doğrudan yanıtlanır.
2. **`evaluate_context` bir routing fonksiyonu**, normal bir node değil — string döndürür ("generate" ya da "retrieve_more"), bu conditional edge'i sürür.
3. **`retrieval_count` sabit bir güvenlik sınırı** — bu olmadan agent, cevabı bilgi tabanında olmayan bir sorguda sonsuza kadar döner.

### RAPTOR (Recursive Abstractive Processing for Tree-Organized Retrieval)

Belge chunk'ları üzerine bir özet ağacı inşa eder. Seviye 0 chunk'larınızdır. Seviye 1 chunk kümelerinin özetleridir. Seviye 2 özetlerin özetleridir. Sorgu zamanında retriever hem özetlerle (geniş sorular) hem de yaprak chunk'larla (spesifik sorular) eşleşir.

### GraphRAG (Microsoft Research)

Düz retrieval yerine belgelerden bir **bilgi grafı** oluşturur -- varlıklar, ilişkiler, topluluk yapısı. Genel sorularda üstün başarı gösterir: "Tüm olay raporlarındaki ana temalar nelerdir?" gibi sorularda bireysel chunk retrieval'ı büyük resmi kaçırır.

### Multi-Modal RAG

Metnin ötesinde RAG -- görseller, tablolar, diyagramları embedding'leyin ve erişin. CLIP gibi modeller kullanarak, doğal dil sorgularıyla mimari diyagramları arayabilirsiniz.

Bunlar en son teknoloji yenilikleri temsil eder. Çoğu prodüksiyon sistemi henüz bunlara ihtiyaç duymaz -- ama var olduklarını bilmek, ne zaman ihtiyaç duyacağınızı fark etmenize yardımcı olur.

## Önemli Çıkarımlar

Üç şey:

1. **Düzeltmeden önce teşhis edin.** Basit RAG üç öngörülebilir şekilde başarısız olur: sorgu uyumsuzluğu, düşük sıralama, eksik bağlam. Her birinin belirli, hedefli bir çözümü vardır.

2. **HyDE ve re-ranking en yüksek yatırım getirisi sağlar.** Bir ekstra LLM çağrısı (HyDE) veya 10 satır kod (re-ranking), retrieval'ı %10-25 iyileştirebilir. Karmaşık şeylerden önce bunları yapın.

3. **Agentic RAG, Bölüm 1 ve 2'yi birleştirir.** Ne zaman, ne ve kaç kez erişeceğine karar veren bir agent. Agent eğitimi ile RAG eğitiminin buluştuğu nokta burasıdır.
