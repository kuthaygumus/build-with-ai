| Metrik | Ne Sorar | Düşük Puan Ne Demek |
|--------|----------|---------------------|
| **Context Precision** | Erişilen chunk'lar ilgili mi? | Retrieval'da çok fazla gürültü var. k'yi azaltın veya re-ranking ekleyin. |
| **Context Recall** | Gerekli tüm bilgiyi bulduk mu? | İlgili belgeler eksik. Chunking'i iyileştirin veya multi-query ekleyin. |
| **Faithfulness** | Yanıt bağlam tarafından destekleniyor mu? | Model bağlamın ötesinde halüsinasyon yapıyor. Prompt'u düzeltin. |
| **Answer Relevancy** | Yanıt soruyu karşılıyor mu? | Model konu dışına çıkıyor. Sistem prompt'unu odaklayın. |

### Uygulama

```python
from ragas import evaluate
from ragas.metrics import (
    faithfulness,
    answer_relevancy,
    context_precision,
    context_recall,
)
from datasets import Dataset

eval_data = {
    "question": [
        "How do I authenticate with the Flight Offers API?",
        "What is the baggage allowance for economy?",
        "Can I modify a booking after ticketing?"
    ],
    "answer": [
        "Use OAuth 2.0 client credentials flow with /v1/security/oauth2/token.",
        "Economy baggage allowance is typically 23kg for checked bags.",
        "Yes, modifications are possible through the Booking Management API."
    ],
    "contexts": [
        ["The Flight API uses OAuth 2.0. Send credentials to /v1/security/oauth2/token..."],
        ["Baggage policies vary by airline. Standard economy: 23kg checked, 8kg carry-on..."],
        ["Post-ticketing changes require the Booking Management API. Some changes incur fees..."]
    ],
    "ground_truth": [
        "OAuth 2.0 client credentials flow via /v1/security/oauth2/token endpoint.",
        "23kg for checked luggage, varies by airline and fare class.",
        "Yes, via Booking Management API, subject to airline rules and possible fees."
    ]
}

results = evaluate(
    Dataset.from_dict(eval_data),
    metrics=[faithfulness, answer_relevancy, context_precision, context_recall],
)
print(results)
# {'faithfulness': 0.92, 'answer_relevancy': 0.88,
#  'context_precision': 0.65, 'context_recall': 0.90}
```

### Puanları Okuma

```text
Faithfulness:       0.92  — Answers are well-grounded
Answer Relevancy:   0.88  — Answers address the questions
Context Precision:  0.65  — Too many irrelevant chunks retrieved
Context Recall:     0.90  — Important info is being found

Diagnosis: Retrieval finds the right stuff but also too much noise.
Action: Add re-ranking or reduce k.
```

def run_golden_tests(rag_chain, tests, run_name="baseline"):
    results = []
    for test in tests:
        answer = rag_chain.invoke(test["question"])

### Tuzak 2: Çelişen Kaynaklar

Bilgi tabanınızda 2023 tarihli bir belge "rate limit: 100/dk" diyor, 2024 tarihli başka biri "500/dk" diyor. RAG ikisini de erişiyor. LLM rastgele birini seçiyor.

**Çözümler**: `version` ve `date` meta verisi ekleyin, retrieval sırasında en güncel olanı filtreleyin, prompt'a "en güncel kaynağı tercih et" ekleyin ve indeksleme sırasında eskimiş belgeleri kaldırın.

```python
# Metadata-aware retrieval
results = vector_store.similarity_search(
    "rate limit for flight API",
    k=5,
    filter={"version": "v2"}  # only latest
)
```

### Tuzak 3: Aşırı Erişim

Yalnızca 2'si ilgili olduğunda 20 chunk erişmek. Sinyal gürültüde boğulur.

**Çözümler**: Geniş erişim yapın (k=20), sonra re-ranking ile ilk 5'i tutun. Veya çeşitli, ilgili sonuçlar için MMR kullanın.

```python
# Retrieve 20, re-rank, keep 5
from langchain.retrievers import ContextualCompressionRetriever
from langchain_cohere import CohereRerank

retriever = ContextualCompressionRetriever(
    base_compressor=CohereRerank(top_n=5),
    base_retriever=vector_store.as_retriever(search_kwargs={"k": 20})
)
```

## Prodüksiyon İçin Ölçeklendirme

### Çok Katmanlı Önbellekleme

Gereksiz hesaplamadan kaçınmak için üç seviyede önbellekleyin:

```python
from cachetools import TTLCache

# Level 1: Don't re-embed the same query
embedding_cache = TTLCache(maxsize=5000, ttl=86400)  # 24h

# Level 2: Same query = same retrieved chunks
retrieval_cache = TTLCache(maxsize=1000, ttl=3600)   # 1h

# Level 3: Exact same question = same answer
answer_cache = TTLCache(maxsize=500, ttl=1800)       # 30min
```

### Asenkron İşleme

Sıralı işlemlerle bloklama yapmayın. Dense ve sparse retrieval'ı paralel çalıştırın:

```python
import asyncio

async def async_rag(question: str) -> dict:
    # Dense + sparse retrieval in parallel
    dense_task = asyncio.create_task(
        vector_store.asimilarity_search(question, k=10)
    )
    sparse_task = asyncio.create_task(
        bm25_retriever.ainvoke(question)
    )
    dense_results, sparse_results = await asyncio.gather(dense_task, sparse_task)

    # Merge, re-rank, generate
    all_results = dense_results + sparse_results
    reranked = reranker.compress_documents(all_results, question)
    answer = await llm.ainvoke(prompt.format(
        context="\n\n".join(d.page_content for d in reranked[:5]),
        question=question
    ))
    return {"answer": answer.content, "sources": reranked[:5]}
```

### Maliyet Optimizasyonu

| Bileşen | Maliyet Faktörü | Optimizasyon |
|---------|-----------------|--------------|
| **Embedding** | Embedding'lenen token'lar | `large` ($0.13/1M) yerine `text-embedding-3-small` ($0.02/1M) kullanın |
| **LLM** | Bağlam token'ları | k'yi azaltın, bağlamı sıkıştırın, basit sorgular için `gpt-4o-mini` kullanın |
| **Vektör DB** | Depolama + sorgular | Boyut azaltma, quantization |
| **Re-ranking** | API çağrıları | Yalnızca başlangıç güveni düşük olduğunda re-ranking yapın |

```python
# Cost-aware model routing
def choose_model(context_length: int) -> str:
    if context_length < 2000:
        return "gpt-4o-mini"   # $0.15/1M input tokens
    return "gpt-4o"             # $2.50/1M — handles long context better
```

```python
class RAGMonitor:
    def track_query(self, question: str, rag_fn):
        start = time.time()
        result = rag_fn(question)
        latency = time.time() - start

        self.log({
            "question": question,
            "latency_ms": latency * 1000,
            "num_chunks": len(result.get("sources", [])),
            "model": result.get("model", "unknown"),
        })

        if latency > 5.0:
            logger.warning(f"High latency: {latency:.1f}s for: {question[:50]}")

        return result
```

## Çok Kiracılı Mimari

Kurumsal ortamda farklı kullanıcılar farklı belgeleri görür. Bunu üretim seviyesinde değil, **retrieval** seviyesinde uygulayın.

```python
class MultiTenantRetriever:
    def retrieve(self, query: str, user_id: str, user_roles: list[str]):
        return self.vector_store.similarity_search(
            query,
            k=10,
            filter={
                "$or": [
                    {"access": "public"},
                    {"owner": user_id},
                    {"allowed_roles": {"$in": user_roles}},
                ]
            }
        )
```

<Aside type="caution">
**Güvenlik**: Her zaman retrieval seviyesinde filtreleyin, üretim seviyesinde değil. Kısıtlı bir belge LLM bağlamına girerse, model sistem prompt talimatlarına rağmen onu ifşa edebilir. Bağlam penceresi güven sınırıdır.
</Aside>

### Kalıp 2: Corrective RAG (CRAG)

Retrieval sonrası, belgelerin gerçekten ilgili olup olmadığını değerlendirin. Değilse, web aramasına geri dönün veya bilgisizliğinizi kabul edin:

```python
def corrective_rag(question: str) -> str:
    docs = retriever.invoke(question)
    score = evaluate_relevance(question, docs)  # LLM-as-judge

    if score >= 4:
        return generate_from_context(question, docs)
    elif score >= 2:
        web_docs = web_search(question)
        return generate_from_context(question, docs + web_docs)
    else:
        return "I don't have reliable information for this question."
```

### Kalıp 3: Self-Reflective RAG

Üret, sonra eleştir, sonra iyileştir. Yanıt tam olarak desteklenene kadar döngüye gir:

```python
def self_reflective_rag(question: str, max_iterations: int = 3) -> str:
    for i in range(max_iterations):
        docs = retriever.invoke(question)
        answer = generate_from_context(question, docs)
        critique = llm.invoke(f"Is this answer fully supported by context? {answer}")

        if "fully supported" in critique.content.lower():
            return answer
        question = llm.invoke(f"Refine query based on: {critique.content}").content

    return answer  # best effort
```

Bu kalıplar birleşir. Her alt pipeline'ı Self-Reflection'lı Corrective RAG kullanan bir Router RAG. Mimari gereksinimleri takip eder: doğruluk ihtiyaçları, gecikme bütçesi, maliyet kısıtlamaları.

## Önemli Çıkarımlar

Bu modülden -- ve tüm RAG serisinden:

1. **Her şeyi ölçün.** Otomatik değerlendirme için RAGAS, regresyon testi için altın test setleri. Ölçemezseniz iyileştiremezsiniz -- ve ne zaman bozulduğunu bilemezsiniz.

2. **Prodüksiyon uç durumlarla ilgilidir.** Ortada kaybolma, çelişen kaynaklar, aşırı erişim, çok kiracılı güvenlik. Her birinin belirli, uygulanabilir çözümleri vardır. Bunları bilin.

3. **Agent + RAG + Araçlar = Kurumsal Yapay Zeka.** Agent akıl yürütür. RAG dayanaklı bilgi sağlar. Araçlar harekete geçmeyi sağlar. Bu üçlü, prodüksiyon sistemlerini üzerine kuracağınız mimari kalıptır.

Bu eğitime "RAG nedir?" diye sorarak başladınız. Prodüksiyon RAG sistemlerini nasıl kuracağınızı, değerlendireceğinizi, ölçeklendireceğinizi ve işleteceğinizi -- ve tam resim için agent'larla nasıl birleştireceğinizi bilerek bitiriyorsunuz. İşte temel bu. Şimdi gidin gerçek bir şey geliştirin.
